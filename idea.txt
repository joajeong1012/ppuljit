# ppuljit 개발 명세서

논리 추론 퍼즐 웹게임. 프론트엔드는 TypeScript와 Vite로 만들고, 게임 판정은 UI와 분리된 순수 로직으로 유지한다. Cloudflare Pages Functions와 D1을 사용하며, 원격 DB 변경은 마이그레이션과 배포 전 별도로 확인한다.

## 1. 기술 스택 및 배포 제안

| 구분 | 제안 | 역할 |
| --- | --- | --- |
| 언어 / 빌드 | TypeScript / Vite | 정적 프론트엔드 |
| 정적 호스팅 | Cloudflare Pages | GitHub 저장소 연동 자동 배포 |
| API / 서버리스 | Cloudflare Pages Functions (Workers 런타임) | 계정·기록 API |
| 데이터베이스 | Cloudflare D1 (SQLite) | 계정, 세션, 리더보드 기록 |

**무료 우선 추천안:** Cloudflare Pages + Workers + D1. 프론트엔드·API·DB를 한 계정에서 관리하고, 무료 사용량 한도 안에서 시작할 수 있다. 현재 공식 문서에 기재된 무료 한도는 Workers 100,000 요청/일, D1 5백만 행 읽기/일·10만 행 쓰기/일·총 5GB다. 한도와 요금은 변경될 수 있으므로 실제 배포 시 다시 확인한다.

- [Workers 가격 및 무료 한도](https://www.cloudflare.com/plans.md)
- [D1 가격 및 무료 한도](https://developers.cloudflare.com/d1/platform/pricing/)
- [Supabase 대안](https://supabase.com/pricing): 관리형 Postgres와 REST API가 편리하지만 무료 프로젝트는 1주 비활성 후 일시 중지될 수 있다.

Cloudflare Pages + Pages Functions + D1 구성이 승인되었다. 계정과 D1 데이터베이스는 아직 프로젝트에 연결하지 않았으며, 배포 단계는 아래 절차를 따른다.

## 2. 로컬 시험 준비

사전 준비:

1. Node.js 22 이상 설치.
2. 저장소를 로컬로 내려받거나 복제하고 `project1` 폴더에서 터미널을 연다.
3. `npm install`로 패키지를 설치한다.
4. `npm run db:migrate:local`로 로컬 D1 테이블을 만든다. 확인 메시지가 나오면 `Y`를 입력한다. 이 명령은 `--local`만 사용하므로 원격 Cloudflare DB에는 적용되지 않는다.
5. `npm run dev:local`로 TypeScript 빌드 후 Pages 로컬 서버를 실행한다.
6. 터미널에 표시되는 `http://localhost:8788` 주소를 브라우저에서 연다. API가 포함된 리더보드를 시험하려면 Vite의 `npm run dev` 대신 Pages 로컬 서버를 사용한다.

기본 검증 순서: 계정 만들기·로그아웃·다시 로그인·새로고침 후 로그인 유지 → 자리 수·속성 수 선택 → 질문·오답 제출 집계 → 정답 제출 → 리더보드 기록 등록 및 설정별 조회. 로컬 D1 데이터는 `.wrangler` 폴더에 저장되며 `.gitignore`에 포함된다.

명령 요약:

```powershell
cd project1
npm install
npm run db:migrate:local
npm run dev:local
```

게임 이름은 **ppuljit**으로 확정한다. 사용자는 아이디와 비밀번호로 계정을 만들고 로그인한다. 아이디는 영문 소문자·숫자·밑줄 3~20자이며, 비밀번호는 8~128자다. 아이디는 대소문자를 구분하지 않는다. 비밀번호 원문은 저장하지 않고 PBKDF2-HMAC-SHA-256 100,000회 해시만 D1에 저장한다. Cloudflare Workers Web Crypto의 반복 횟수 한도에 맞춘 설정이다. 로그인 세션은 무작위 토큰의 SHA-256 해시로 D1에 저장하고, 브라우저에는 HttpOnly·SameSite 쿠키를 발급한다. 세션 유효 기간은 30일이다. 리더보드 기록의 이름은 인증된 계정 아이디를 서버가 설정한다. 이메일 인증과 비밀번호 재설정은 제공하지 않으므로 사용자가 비밀번호를 기억해야 한다. 로컬 시험에는 Cloudflare 계정이 필요하지 않다.

## 3. 게임 설정 및 진행 규칙

- 한 판은 정답 카드 조합 하나를 찾는 단일 퍼즐이다. 스테이지 진행은 없다.
- 시작 전에 카드 자리 수와 속성 종류 수를 선택한다.
- 자리 수: 3~10개.
- 속성 종류 수: 1~3개. 선택 수에 따라 아래 속성을 순서대로 사용한다.
  1. 색상: 빨강, 파랑, 노랑
  2. 도형 추가: 원, 세모, 네모
  3. 채움 추가: 채움, 줄무늬, 윤곽
- 각 카드에는 선택된 속성 그룹마다 값이 하나씩 있다. 각 속성 값은 중복될 수 있다.
- 시드와 설정(자리 수, 속성 종류 수)이 같으면 같은 정답 조합을 생성한다. 공유 링크에는 시드와 설정을 포함한다.
- 코스트, 오답 패널티, 시간 제한은 없다. 질문 횟수와 완료 시간만 측정한다.
- 질문 횟수에는 YES/NO 질문과 틀린 정답 제출 횟수를 모두 포함한다. 맞은 마지막 제출은 더하지 않는다.
- 질문 응답은 YES/NO로 제공하고, 질문 내용과 응답을 게임 중 기록한다.
- 정답 조합 제출이 맞으면 게임을 완료하고 시간을 고정한다. 잘못된 제출은 안내만 표시한다.

## 4. 데이터 및 질문 판정

카드 하나는 비트 플래그를 OR한 정수로 표현한다.

| 속성 그룹 | 값 |
| --- | --- |
| 도형 | `SHAPE_CIRCLE`, `SHAPE_TRIANGLE`, `SHAPE_SQUARE` |
| 색상 | `COLOR_RED`, `COLOR_BLUE`, `COLOR_YELLOW` |
| 채움 | `FILL_SOLID`, `FILL_STRIPED`, `FILL_OUTLINE` |

지원하는 질문 유형:

- `POSITION_CHECK`: 지정 자리의 특정 속성값 존재 여부.
- `RELATION_EQ`: 두 자리의 선택 속성 그룹 값이 같은지 여부.
- `COUNT_COMPARE`: 전체 카드 중 특정 속성값을 가진 수량과 기준값 비교 (`==`, `!=`, `>`, `<`, `>=`).

사용할 수 없는 속성 그룹은 질문 선택지에서 제외한다. 판정기는 순수 함수이며 자리 인덱스와 마스크의 유효성을 확인한다.

## 5. 리더보드 규칙

리더보드는 **같은 자리 수와 같은 속성 종류 수**를 선택한 완주 기록만 한 그룹으로 조회한다. 동일한 설정 안에서 서로 다른 시드의 퍼즐 기록을 비교하는 안을 권장한다. 시드까지 같게 묶으면 기록 풀이 적어질 수 있으므로 기본 그룹 조건에는 포함하지 않는다.

기록에 필요한 필드 제안:

```text
nickname, seed, slots, attributes, questionCount, elapsedMilliseconds, createdAt
```

한 판을 성공적으로 완료하면 로그인 계정의 아이디로 기록을 자동 등록한다. 게스트는 플레이할 수 있지만 기록은 바로 저장되지 않는다. 게스트가 완료 후 로그인하거나 회원가입하면 해당 계정에 기록을 등록한다. 서버가 세션을 검증하고 계정 아이디를 기록에 사용하므로 클라이언트가 리더보드 이름을 임의로 지정할 수 없다.

로그인 계정은 리더보드에서 본인 기록을 삭제할 수 있다. 소유자 정보가 추가되기 전에 생성된 기존 기록은 계정과 연결할 수 없어 삭제 버튼을 제공하지 않는다.

**확정된 정렬:** 질문 횟수 오름차순, 동률이면 완료 시간 오름차순. 두 값이 모두 같으면 먼저 등록한 기록이 앞선다.

API 초안:

- `POST /api/records`: 완료 기록 등록.
- `GET /api/records?slots=5&attributes=2&limit=10`: 같은 설정의 상위 기록 조회.
- `DELETE /api/records?id=<record-id>`: 로그인한 사용자의 본인 기록 삭제.

**확정된 정책:** 초기 공개 버전은 비검증 캐주얼 리더보드로 운영한다. 로그인 계정만 기록을 제출할 수 있지만, 질문 수와 시간은 클라이언트가 보내므로 여전히 조작될 수 있으며 API는 입력 범위만 검증한다. 비밀키를 프론트엔드에 넣지 않는다.

## 6. 결과 공유

클립보드 공유 문구에 시드, 설정, 완료 여부, 질문 횟수, 경과 시간을 포함한다. 도전 링크는 동일 시드와 퍼즐 설정을 재현해야 한다.

```text
🧩 ppuljit #20261019
🧠 퍼즐: 5자리 · 속성 2개
🏆 클리어 완료
🔍 질문 횟수: 19회
⏱️ 경과 시간: 03:34.5
👉 도전하기: https://example.com/?seed=20261019&slots=5&attributes=2
```

## 7. 현재 구현 범위

- 완료: ppuljit 브랜딩, 시드 기반 퍼즐 생성, 설정 화면(3~10자리·속성 1~3개), 세 가지 질문 유형, 소거 메모장, 정답 제출, 질문 횟수 및 타이머, 결과 공유, Pages Functions 리더보드 API, D1 마이그레이션.
- 완료: 첫 화면의 설정별 리더보드와 게임 시작 선택 창, 로그인·게스트 플레이, 초보자용 게임 안내, 질문 답변 강조, 소거 메모장 초기화, 빈 정답 입력, 3장 카드 정렬.
- 완료: 아이디·비밀번호 계정 생성 및 로그인, D1 사용자·세션 테이블, 비밀번호 해시 저장, HttpOnly 세션 쿠키, 로그아웃, 계정 완료 기록 자동 등록 및 소유자 기반 기록 삭제.
- 보류: 이메일 인증, 비밀번호 재설정 및 로그인 시도 제한.
- 보류: Cloudflare 계정 연결, 원격 D1 생성, 실제 Pages 배포 및 사용자 도메인 연결.
- 공개 기록은 사용자 입력을 서버가 범위 검증하는 방식이며, 질문 수와 완료 시간을 독립적으로 재검증하지 않는다. 비검증 캐주얼 운영을 승인받았다.

## 8. Cloudflare 연결 및 배포 준비

Cloudflare 계정을 만들었다면 다음 순서로 D1을 연결한다.

1. Cloudflare Dashboard에서 **Workers & Pages → D1 SQL Database → Create**를 선택하고 `ppuljit` 데이터베이스를 만든다.
2. 데이터베이스 상세 화면의 UUID(Database ID)를 복사한다.
3. `wrangler.toml`의 `database_id`에 있는 0으로 된 예시 값을 복사한 UUID로 교체한다. `database_name = "ppuljit"`과 `binding = "DB"`는 그대로 둔다. 이 바인딩을 통해 Pages Functions가 D1을 사용한다.
4. 먼저 로컬에서 확인할 때는 `npm run db:migrate:local`과 `npm run dev:local`을 실행한다. 로컬 DB와 원격 DB는 별도다.
5. 배포 전 터미널에서 `npx wrangler login`을 실행해 Cloudflare에 인증한다. 그다음 `npm run db:migrate:remote`로 `0001`(리더보드), `0002`(계정·세션), `0003`(기록 소유자) 마이그레이션을 원격 D1에 적용한다. `0003`은 기존 기록을 삭제하지 않고 소유자 필드를 추가하며, 기존 기록은 소유자가 지정되지 않아 삭제할 수 없다. 원격 명령은 실제 Cloudflare 데이터를 변경한다.
6. Cloudflare Dashboard의 **Workers & Pages → Create application → Pages → Connect to Git**에서 GitHub 저장소를 선택한다. 프로젝트 루트는 `project1`, 빌드 명령은 `npm run build`, 빌드 출력 디렉터리는 `dist`로 설정한다. `wrangler.toml`의 D1 바인딩을 Pages 프로젝트가 읽는지 확인하고 첫 배포 후 회원가입·로그인·기록 등록을 점검한다.

Database ID를 받기 전에는 `wrangler.toml`의 예시값을 그대로 두고 원격 마이그레이션을 실행하지 않는다. Cloudflare 계정 인증, 원격 데이터베이스 변경, 배포는 사용자가 직접 확인한 뒤 진행한다.
